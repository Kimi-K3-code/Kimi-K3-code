## ⚖️ 3. المهمة الأولى: تحصين ملف الريفرش والاختبارات لبيئة الويندوز (RULE 39)

> 📌 **نص القاعدة الدستورية الجديدة المستخرجة من `Root/قواعد` (RULE 39):**
> **«مفيش حاجة اسمها الوكيل شغال على بيئة لينكس فـ الكود يشتغل عنده وخلاص وإحنا بيئتنا ويندوز! أي مشروع وأي سكربت بنعمله لازم يشتغل 100% على نفس بيئتنا الأصلية (ويندوز) بالمللي. مفيش كراش يضرب عشان ترميز، ولا ينسى سطر ضبط الكونسول للعربي، ولا ينسى encoding='utf-8' لقراءة الملفات، وممنوع تكرار الموضوع ده نهائياً!»**

### 🔍 الأدلة الجنائية من الاختبار الميداني الحي (Live Runtime Tracebacks):
أثناء تشغيل كود `PR #1` حياً في بيئة الويندوز المحلية الحقيقية داخل تيرمينال PowerShell، ظهر عطلان ناتجان عن افتراض بيئة Linux/POSIX:

#### 1️⃣ كراش الطباعة العربية في `03_syntx_refresh.py`:
```text
Traceback (most recent call last):
  File "03_syntx_refresh.py", line 200, in main
    emit(f'فحص السجل {index}/{len(accounts)}...', 'cyan')
  File "03_syntx_refresh.py", line 147, in emit
    print(message)
  File "encodings/cp1252.py", line 19, in encode
    return codecs.charmap_encode(input,self.errors,encoding_table)[0]
UnicodeEncodeError: 'charmap' codec can't encode characters in position 0-2: character maps to <undefined>
```
- **السبب الجذري:** تيرمينال الويندوز يعمل افتراضياً بترميز ANSI/CP1252. في غياب تهيئة `sys.stdout`، ينهار السكربت فور محاولة طباعة أي نص عربي أو إيموجي ملون.

#### 2️⃣ فشل الاختبار رقم 27 في `test_syntx_refresh.py`:
```text
Traceback (most recent call last):
  File "test_syntx_refresh.py", line 265, in test_har_payloads_without_using_captured_credentials
    for entry in json.loads(path.read_text())['log']['entries']:
  File "encodings/cp1252.py", line 23, in decode
    return codecs.charmap_decode(input,self.errors,decoding_table)[0]
UnicodeDecodeError: 'charmap' codec can't decode byte 0x90 in position 5260: character maps to <undefined>
```
- **السبب الجذري:** استدعاء `path.read_text()` بدون تحديد `encoding="utf-8"` صراحة، مما جعل بايثون على ويندوز يحاول فك تشفير ملف الـ HAR بترميز CP1252.

### 🛠️ الإجراء الجراحي المطلوب بالتحديد:
1. **في `03_syntx_refresh.py`:**
   إضافة كتلة التحصين التالية فوراً بعد استيراد مكتبات النظام الأساسية وقبل أي استدعاء لدوال الطباعة:
   ```python
   # ضبط ترميز الكونسول لدعم اللغة العربية والإيموجي على ويندوز
   if sys.platform == "win32":
       try:
           sys.stdout.reconfigure(encoding="utf-8", errors="replace")
           sys.stderr.reconfigure(encoding="utf-8", errors="replace")
       except Exception:
           pass
   ```
2. **في `test_syntx_refresh.py`:**
   تعديل السطر 265 ليصبح:
   ```python
   # BEFORE (L265):
   # for entry in json.loads(path.read_text())['log']['entries']:
   # AFTER:
   for entry in json.loads(path.read_text(encoding="utf-8"))['log']['entries']:
   ```
   وفحص كافة استدعاءات قراءة وكتابة الملفات داخل ملف الاختبار للتأكد من وجود `encoding="utf-8"` صراحة.
3. **التحقق:** اجتياز جميع الاختبارات الـ 27 بنجاح تام بنسبة 100% تحت بيئة Windows.

### 🏛️ الركائز المعمارية الأربعة لملف الشات (`01_syntx_chat.py`):

#### 1️⃣ الاستدعاء التلقائي المباشر في الخلفية (Same-Directory Background Execution):
- في كل مرة يُشغَّل فيها `01_syntx_chat.py` (سواء عبر Run أو التيرمينال أو استدعاء خارجي)، يقوم فورياً باستدعاء ملف التسجيل `02_syntx_register.py` الموجود معه **في نفس المسار المباشر حصراً** (`BASE_DIR = pathlib.Path(__file__).resolve().parent`).
- يتم الاستدعاء عبر عملية خلفية منفصلة تماماً (`subprocess.Popen`) بتمرير المعاملات التالية:
  ```python
  cmd = [sys.executable, str(BASE_DIR / "02_syntx_register.py"), "--max", "5", "--no-loop"]
  ```
- مع كتم تدفقات الإخراج (`stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL`) لضمان عدم تشويش شاشة الشات، واستخدام أعلام فصل العمليات المناسبة لنظام التشغيل (`creationflags=subprocess.CREATE_NEW_PROCESS_GROUP` على ويندوز).

#### 2️⃣ فصل دورات الحياة التام (Decoupled Lifecycles):
- استقلال زمني مطلق: إذا أجاب الشات واستلم المستخدم الرد خلال 5 ثوانٍ، يخرج الشات ويغلق فورياً.
- عملية تسجيل الحسابات في الخلفية تستمر في عملها بهدوء حتى تنتهي من توليد الـ 5 حسابات وتسجيلها في `accounts_syntx.json` دون أن تعطل الشات أو ينتظرها المستخدم لحظة واحدة.

#### 3️⃣ حماية الموارد وضمان الإنهاء التلقائي (Zero Deadlock & Strict Timeouts):
- ملف الإنشاء `02_syntx_register.py` محكوم بمهل صارمة:
  - مهلة انتظار الـ OTP: بحد أقصى 15 ثانية (مع الإسقاط السريع للدومينات البطيئة).
  - المهلة الكلية لإنشاء حساب واحد: 180 ثانية (3 دقائق).
  - الحد الأقصى الرياضي لإنهاء الـ 5 حسابات هو 15 دقيقة (5 × 3 ق = 15 دقيقة كحد أقصى مطلق).
- بالتالي، العملية الخلفية مضمونة الإنهاء الذاتي بنجاح أو فشل دون أي خطر لتراكم العمليات الزومبي (Zombie Processes) أو استنزاف الذاكرة.

#### 4️⃣ تطهير الكود القديم وتثبيت الـ Blueprint في `Config` والبانر:
- **تطهير الكود الميت والتكرار (DRY Compliance):** يحتوي ملف `01_syntx_chat.py` حالياً على كود قديم مكرر لمحرك تسجيل الحسابات والبريد المؤقت (`TempMailClubProvider`). المطلوب إزالة هذا الكود المكرر من ملف الشات، لأن مهمة التسجيل أصبحت حصراً ومستقلاً من اختصاص `02_syntx_register.py`.
- **توثيق المعمارية في كلاس `Config` وبانر السكربت:**
  تثبيت معالم هذه المعمارية في متغيرات كلاس `Config`:
  ```python
  refill_batch_size: int = 5              # عدد الحسابات المطلوب توليدها في كل دورة خلفية
  auto_refill_on_start: bool = True       # استدعاء ملف الإنشاء تلقائياً في الخلفية عند بدء الشات
  register_script_name: str = "02_syntx_register.py"
  ```
  وتوثيقها في البانر العلوي التوضيحي للسكربت لتكون النموذج المعماري القياسي لكافة المزودين القادمين بالمنظومة.
- **الالتزام الصارم بـ RULE 39:** التأكد من وجود كتلة تحصين الويندوز `sys.stdout.reconfigure(encoding="utf-8")` واستخدام `encoding="utf-8"` الصريح في كافة عمليات قراءة وكتابة الملفات (`accounts_syntx.json`, `chat_send.txt`, `chat_reply.txt`).
